# 제어 입력 끊김 및 정지 우선순위 핫픽스

## 변경된 동작

- `decision_auto`: 차선 명령과 신호등·횡단보도 판단을 모두 수신한 뒤에만 주행을 허용한다. 차선 명령은 0.5초, 두 신호 판단은 각각 1.0초 이내의 입력이어야 한다. 기본값은 실차 측정으로 선정한 값이 아니며 YAML에서 조정한다.
- 정지 신호와 필수 입력 만료는 장애물 회피보다 우선한다. 정지 시 신선한 차선 명령이 있으면 조향은 유지하고 구동 입력만 0으로 만든다. 차선 입력도 없으면 조향도 0이다.
- `joy_to_twist`: `/joy` 수신이 0.5초 이상 끊기면 마지막 구동·조향을 반복하지 않고 0 명령을 발행한다.
- `cmd_mux`: 수동 명령 만료 시 0을 발행한다. 자동 명령이 0.3초 넘게 끊기면 수동 명령으로 자동 전환하지 않고 STOP에 머문다. 다시 움직이려면 사용자가 모드를 선택해야 한다.
- 입력 유효시간은 시스템 시각 보정의 영향을 받지 않는 `time.monotonic()`으로 측정한다.

기본 launch는 여전히 `lane_trace`, `sign_detect`, `obs_evade`를 실행하지 않는다. 자동 주행에 필요한 차선·신호 노드를 별도로 실행해야 한다. 누락된 인지 입력을 우회해서 주행하지 않는다. 인지 입력 만료로 정지한 경우 신선한 입력이 모두 복구되면 자동 명령은 재개된다. 이는 cmd_mux의 자동 명령 만료에 따른 STOP 잠금과 다르다.

## 검증

저장소 루트에서 실행:

```bash
python3 -m unittest discover -s tests -v
```

실제 노드의 콜백을 가짜 시계·메시지·publisher로 실행한다. 9개 테스트는 초기 입력 누락, 차선/각 신호 입력 만료, 입력 복구, 정지와 회피의 동시 발생, 회피 만료, 조이스틱 중단의 mux 전파, 수동 publisher 중단, 자동 명령 중단 시 STOP 유지를 검증한다. ROS/DDS, launch 실행, USB 및 모터를 검증한 것은 아니다.

## 남은 실차 확인과 범위

- 바퀴를 띄운 상태에서 각 publisher 종료 및 장치 분리 시 실제 정지를 확인한다. 노드 처리 지연과 타이머 주기 때문에 설정값이 정확한 물리 정지 시간을 의미하지 않는다.
- 이 검사는 메시지 도착 여부를 확인한다. 카메라 영상이 계속 들어오지만 차선을 검출하지 못하는 경우, 드라이버가 오래된 조이스틱 상태를 계속 발행하는 경우는 별도 검증·수정 대상이다.
- 라이다 연결 감시, 회피 동작의 중단·재개 상태 관리, Arduino 보정 응답 처리, serial_sender 자체 타임아웃은 이번 범위에 포함하지 않는다. 시리얼 중단에 대한 기존 Arduino watchdog은 2초다.
- gap_follow/wall_follow를 decision_auto와 함께 `/cmd_auto`에 발행하면 이 판단을 우회할 수 있다. 기본 차선·신호 주행 시험에서는 decision_auto만 `/cmd_auto`를 발행하는지 확인한다.
- 조향 부호·출력·센서 ROI·Hokuyo 드라이버는 변경하지 않았다.

## 원격 변경 확인

작업 시작 시 clean working tree에서 fetch 후 변경을 확인하고 fast-forward로 가져온다. 로컬 변경이 있으면 먼저 diff를 확인하고 커밋 등으로 보존한다. 자동 reset/stash는 하지 않는다.

```bash
git fetch origin
git status --short --branch
git log --oneline HEAD..origin/main
git diff HEAD...origin/main
git pull --ff-only
```

다른 브랜치의 변경은 main의 pull에 포함되지 않는다. 이번 작업 시 `origin/ganghee`의 카메라 헤드리스/모델 경로 변경(`03747cb`)은 main과 별개였으며 병합하지 않았다.
