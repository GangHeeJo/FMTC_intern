이 문서는 2026-10-11 네이티브 Ubuntu에서 실차(Arduino + 카메라)로 자동 주행을 처음 돌려 본 날의 결과를 정리한 것이다.
(1) 지금 어디까지 됐는지, (2) 조향이 어떻게 만들어지고 어떻게 모터까지 가는지, (3) 차선을 잘 따라가도록 튜닝하는 방법과 순서,

## 1. 지금 어디까지 됐나

### 1.1 동작하는 것 [확인]

| 항목 | 상태 |
|---|---|
| 환경 | 네이티브 Ubuntu 22.04 + ROS2 humble 설치/빌드 완료, 모든 패키지 등록 |
| USB | Arduino가 몇 초마다 끊기던 문제의 큰 원인은 **USB 자동 절전**이었고 `usbcore.autosuspend=-1`을 GRUB에 영구 적용해 해결 |
| 시리얼 | `serial_sender`가 USB가 끊겨도 죽지 않고 정지 상태로 대기하다 자동 재연결 |
| 수동 주행 | Xbox 유선 컨트롤러로 전진/후진/조향 동작 (A=자동, B=수동, **Y=정지**) |
| 자동 주행 체인 | 카메라 → `lane_trace` → `decision_auto` → `cmd_mux` → `serial_sender` → Arduino 전 구간 입출력 확인 |
| 직선 구간 추종 | 기준선 설정에서 조향이 큰 값에서 시작해 **0 근처로 수렴**하고 전진 명령이 끊기지 않음 (60초 기록 `bag5` 기준) |
| 코너(오른쪽) | 같은 기준선에서 코너 진입 시 조향이 **오른쪽(-300 ~ -600)으로 유지**됨 |

### 1.2 아직 안 되는 것 [확인]

| 문제 | 증상 | 핵심 원인 |
|---|---|---|
| 코너에서 차선을 놓침 | 코너 위주 구간 검출률 약 26% | 오른쪽 경계선이 코너에서 휘어 화면 밖으로 빠지고, 인식 조건(직선·기울기 0.4 이상)에 안 맞음 |
| 차가 트랙 중앙 쪽일 때 차선을 놓침 | 선이 보이는데도 `NO LANE`, 전진 0 | 중앙 쪽에서는 경계선이 완만하게 보여(기울기 약 0.35) 기울기 조건 0.4에 걸림 |
| 조향이 가끔 최대(±1000)로 튐 | 코너 구간에서 5~35% | 주차 박스선 같은 엉뚱한 선이 한두 프레임 후보로 잡힘 |
| 속도를 올리면 이탈 | `th_scale=600`에서 트랙 밖으로 벗어남 | 조향 능력(모터 한계, 반응 속도)을 속도가 앞지름 |
| 조향/전진이 번갈아 멈칫 | 사용자가 육안으로 관찰 | 명령은 끊기지 않았음(전진 100%) → 액추에이터 쪽(전력 간섭 등) 의심. **[추정]**, 미검증 |

### 1.3 아직 검증하지 못한 것

- 조향과 전진이 번갈아 멈칫하는 원인(수동 모드에서 "조향 없이 전진" vs "조향하며 전진" 비교 시험을 못 함)
- `min_slope:=0.35`, `steer_filter_n:=5`의 실제 주행 효과 (기록 영상 재생에서는 개선 확인, 현장 주행은 아직)
- `sign_detect`(신호등/횡단보도)의 실제 인식, 라이다 노드(`obs_evade` 등), 통합 launch 장시간 주행
- 허브 연결의 장시간 안정성 (아래 USB 절 참고)

## 2. 시스템 구조와 신호 흐름

### 2.1 노드와 토픽

```
usb_cam(/cam_lane)   → /cam_lane/image_raw ─→ lane_trace ──→ /cmd_lane  ─┐   (약 11Hz, 선이 검출된 프레임마다 발행)
usb_cam(/cam_front)  → /cam_front/image_raw → sign_detect ─→ /light_stop, /cross_stop ─┤
                                                                           ├→ decision_auto → /cmd_auto (10Hz) ─┐
라이다(현재 미사용)  → /scan ─→ obs_evade ─→ /cmd_obs (launch에 미포함)    ─┘                                    │
조이스틱 /joy → joy_to_twist → /cmd_manual ────────────────────────────────────────────────────────────→ cmd_mux → /cmd_out (20Hz) → serial_sender → Arduino
                                                                                         (A/B/Y 버튼으로 모드 전환)
```

| 노드 | 하는 일 | 중요한 안전 동작 |
|---|---|---|
| `lane_trace` | 영상에서 오른쪽 차선을 찾아 `/cmd_lane`(Twist) 발행 | 차선 미검출 시 `linear.x=0` |
| `decision_auto` | 차선/신호/장애물 명령을 `/cmd_auto` 하나로 병합 | 차선 입력이 0.5초, 신호 입력이 1.0초 넘게 안 오면 `linear.x=0`(STALE INPUT) |
| `cmd_mux` | 모드(수동/자동/정지) 선택, `/cmd_out` 발행 | **STOP으로 시작**. 자동에서 `/cmd_auto`가 0.3초 넘게 끊기면 0 발행 후 수동으로 전환. STOP은 1초간 0을 내고 이후 침묵 |
| `serial_sender` | `/cmd_out`을 `TH:<n> STN:<n>` 텍스트로 변환해 시리얼 전송 | 끊기면 정지 유지 + 1초마다 재연결. 재연결 직후 2초는 전송 안 함 |
| Arduino 펌웨어 | 명령을 모터/조향으로 실행 | 패킷이 2초 넘게 안 오면 정지 (`PACKET_TIMEOUT_MS`) |

주의: 신호 입력(`/light_stop`, `/cross_stop`)은 `sign_detect`가 떠 있어야 나온다. 자동 주행은 **세 노드(launch, lane_trace, sign_detect)가 모두** 있어야 한다.
카메라 1대만 쓰는 벤치 시험은 `decision_auto`에 `-p require_signals:=false`.

### 2.2 `lane_trace` 인식 알고리즘 (`lane_trace/lane_trace/lane_trace.py`의 `lane_detect`)

한 프레임에서 순서대로:

1. **흰색 마스크**: HLS 색 공간에서 `L(밝기) ≥ 100`인 점 전부 (`lower_white=[0,100,0]`). 기준이 매우 느슨해서 밝은 바닥/차량/창문도 흰색으로 잡힌다. 조도가 바뀌면 이 값이 첫 번째 용의자다.
2. **관심 구역(ROI) 자르기**: 사각형 `(100, roi_top) ~ (640, 450)`. 기본 `roi_top=220`. (영상 크기 640×480)
3. **Canny 엣지**: 가우시안 블러 후 중앙값 기준 자동 임계값 (`sigma=0.33`).
4. **Hough 직선 검출**: `HoughLinesP(threshold=20, minLineLength=65, maxLineGap=10)`.
5. **후보 선 필터** (모두 만족해야 차선 후보):
   - 선분 중점의 x가 `right1(330) < x < right2(640)` — 화면 오른쪽 절반만 본다
   - 중점이 대각선 `m(x−620) + (380−y) > 0` 위쪽 (`m=0.3`) — 화면 아래쪽 모서리 제외
   - `|기울기| > min_slope` (기본 0.4) — 수평에 가까운 선(주차 박스 가로선 등) 제외
6. **피팅**: 후보 선분들의 끝점 전부를 직선으로 피팅(`polyfit`), `y=300`에서의 x를 `x_value`로 사용.
   기울기는 후보들의 평균 기울기를 각도로 바꾼 `slope_avg = |atan(평균기울기)|` (rad).
7. **조향 계산**(아래 3절).

핵심 한계: **오른쪽 경계선 하나, 직선 하나**만 본다. 중앙 점선은 ROI 밖(x<330)이라 무시된다. README에 있던 예전 ROS1 버전은 좌우 양쪽 차선을 썼으나 ROS2 이식 때 빠졌다. **[확인]**

## 3. 조향이 만들어지는 과정 (수식과 단위)

### 3.1 `lane_trace` 안에서

```
steering_rad = a_rad × (slope_avg − guide_slope) + b_rad × (x_value − guide_x)
steering_rad = clip(steering_rad, −0.4, +0.4)

angular.z   = − steering_rad × 2500          # 0.4 rad → ∓1000
linear.x    = linear_speed (검출됨) / 0 (미검출, lost_hold_s 이후)
```

- 기본 `a_rad = 0.5`, `b_rad = 0.0027`. (현재 노드 파라미터로는 **노출되어 있지 않음**, `lane_detect` 함수 인자로만 있음. 3.4 참고)
- `guide_x`, `guide_slope`는 "차가 이상적인 자세일 때 선이 있어야 할 위치(px)와 기울기(rad)". 기본값 550, 1.11은 예전 카메라/트랙 기준이다.
- 오차가 0이면 조향 0(직진). 선이 기준보다 **오른쪽**(x가 큼)이거나 **더 가파르면**(slope_avg 큼) `steering_rad`가 양수가 되어 `angular.z`는 **음수 = 오른쪽 조향**이다.

각 항의 힘 (단독으로 포화되는 크기):

| 항 | 1단위당 | 단독으로 최대(0.4 rad)가 되는 오차 |
|---|---|---|
| 위치 `b_rad` | 1px = 0.0027 rad = `z` 6.75 | **약 148 px** |
| 각도 `a_rad` | 1 rad = 0.5 rad | **약 0.8 rad (46°)** |

기본 기준값(1.11)과 보정값(0.524)의 차이만으로도 각도 항이 `0.5×(0.524−1.11) = −0.29 rad`(= `z +733`)를 만든다. 이 때문에 이상적인 자세에 놓아도 조향이 +850 근처로 나와 한쪽으로 계속 꺾였다. **[확인]**

### 3.2 조향 부호 규칙

| 값 | 의미 |
|---|---|
| `angular.z` **양수** | **왼쪽** 조향 (관측: `z=+1000`이 유지될 때 차가 왼쪽으로 꺾임) |
| `angular.z` **음수** | **오른쪽** 조향 |
| 조이스틱 | 오른쪽 스틱을 오른쪽으로 밀면 축값이 음수 → `angular.z` 음수 → 오른쪽 (일치) |

자동 주행에서 차가 차선 **왼쪽**에 있으면 선이 화면에서 **오른쪽**(x 큼)으로 보이고 `z`가 음수(오른쪽)가 되어 차선 쪽으로 돌아온다. 코드 논리와 기준선 주행 기록(조향이 0으로 수렴)이 일치한다. **[확인]**

### 3.3 `serial_sender` → Arduino 단위 변환

```
TH  = linear.x × th_scale                       # th_scale: s1_stack.yaml, 기본 1000 (현재 임시 450)
STN = angular.z  (그대로, ±1000으로 clamp, |STN|<50 이면 0)   # stn_deadzone=50
전송: "TH:<TH> STN:<STN>\n"  (20Hz)
```

Arduino(`Arduino/S1/S1.ino`):

| 값 | 변환 | 예 |
|---|---|---|
| 구동 PWM | `PWM = |TH|/1000 × DRIVE_PWM_MAX(180)` (`DRIVE_MIN_PWM=0`, 즉 최소 구동 보정 없음) | `th_scale=450` → TH 450 → **PWM 81/255**, `200`→36, `600`→108 |
| 조향 목표 각도 | `angle° = STN × 30 / 1000` (최대 ±30°) | `z=1000` → 30°, `z=100` → 3° |
| 조향 모터 | **DC 모터 + 가변저항(포텐셔미터) 위치 피드백**. 목표와 차이가 **4° 초과**면 PWM **150**으로 돌리고, **3° 이하**가 되면 멈춤 (히스테리시스 방식 on/off) | 매 10ms 갱신 |
| 시작 | 전원이 켜질 때 `calibrateSteering()`을 실행해 조향을 끝에서 끝까지 움직여 범위를 잰다 (포트를 열 때마다 보드가 리셋되므로 매번 일어남) | |

중요한 성질:
- 조향 입력 `z`는 거의 그대로 **각도 목표**가 된다. `z=100`(3°)보다 작은 변화는 모터가 반응하지 않는다.
- 조향 모터는 **세게(PWM 150) 켜졌다 꺼지는** 방식이라 목표가 계속 조금씩 움직이면 짧게 "달달" 거릴 수 있다. **[추정]**
- 구동 모터는 PWM 수십 단위의 약한 구동이다. 조향 모터 PWM(150)이 훨씬 커서 조향이 돌 때 전원이 흔들려 구동이 멈칫하는 것이 아닌지 의심한다. **[추정, 미검증]**

### 3.4 아직 파라미터로 안 열린 것 (코드 수정 필요)

`a_rad`, `b_rad`(조향 게인), `right2`, `m`/`n`(대각선), Hough 파라미터, 색 필터의 `L ≥ 100`, `-2500` 스케일, 클램프 `±0.4`.
튜닝하다 필요해지면 `lane_detect` 인자(이미 `a_rad`, `b_rad`는 인자)를 `declare_parameter`로 노드에 열면 된다 (`min_slope`, `right1`, `roi_top`을 연 방식과 동일).

## 4. `lane_trace` 파라미터 레퍼런스

실행 형식: `ros2 run lane_trace lane_trace --ros-args -p 이름:=값 ...` (정수/실수 모두 가능)

| 파라미터 | 기본값 | 의미와 영향 | 올리면 / 내리면 | 주의 |
|---|---|---|---|---|
| `linear_speed` | 0.5 | 차선 추종 중 `linear.x` (0~1). 실제 속도는 `× th_scale` | 올리면 빠름 | `serial_sender`가 1.0으로 clamp. 자동 속도 = `linear_speed × th_scale` |
| `guide_x` | 550 | 이상적 자세에서 선의 x(px). **차선과의 거리**를 정함 | 키우면 차가 선에서 **더 멀리**(왼쪽으로), 줄이면 가깝게 **[추정, 미검증]** | 20~30px씩만 바꿀 것 |
| `guide_slope` | 1.11 | 이상적 자세에서 선의 기울기(rad). **차의 헤딩(방향)** 기준 | 보정값에서 벗어나면 항상 한쪽으로 쏠림 | 반드시 `calib_pose.py`로 측정 (현재 보정값 0.524) |
| `lost_hold_s` | 0.0 | 차선을 놓친 뒤 이 시간(초) 동안 전진과 **마지막 조향 유지**. 넘으면 정지 + 조향 중앙 복귀 (`>0`일 때만 중앙 복귀) | 키우면 코너에서 잠깐 놓쳐도 계속 감 | 너무 크면 선을 완전히 잃은 채 달림. 기준선 1.5 |
| `min_slope` | 0.4 | 후보 선의 최소 기울기 | **낮추면** 완만한 선(차가 중앙일 때)도 잡지만 수평선(주차 박스)을 잡아 조향이 튐 | 0.35까지는 영상 재생에서 이득, 0.3 이하·0.1은 해로움 |
| `right1` | 330 | 인식 구역 왼쪽 경계(px) | 낮추면 화면 가운데도 봄 | 낮출수록 엉뚱한 선 증가(영상 재생에서 해로움) |
| `roi_top` | 220 | 인식 구역 위쪽 경계(px). 클수록 **가까운 곳만** 봄 | 키우면 직선 구간 안정, **위치가 다르면 검출률 붕괴(2~28%)** | 기본 유지 권장 |
| `steer_filter_n` | 1 | 조향 중앙값 필터 길이(1=끔). 한두 프레임 튀는 값 제거 | 키우면 부드럽지만 반응이 느려짐 | 5가 영상 재생에서 튐 5.6%→2.0% |
| `debug_view` | false | OpenCV 창 표시 (오버레이, 흰색 마스크) | | 디스플레이 필요 |

`s1_stack.yaml`(로컬 임시값, **커밋 금지**): `th_scale: 450`, 조이스틱 `axis_steer: 3`, `axis_drive: 1`(Xbox 기준).

### 4.1 현재 기준선 (가장 잘 됐던 설정)

```bash
# 터미널 1: th_scale 450 (s1_stack.yaml) 상태로
ros2 launch s1_stack s1_stack.launch.py
# 터미널 2
ros2 run lane_trace lane_trace --ros-args -p linear_speed:=1.0 -p lost_hold_s:=1.5 -p guide_slope:=0.524 -p guide_x:=531
# 터미널 3
ros2 run sign_detect sign_detect --ros-args -p model_path:=$HOME/FMTC_intern/sign_detect/best_0808.pt
```

모든 터미널에서 먼저 `source /opt/ros/humble/setup.bash && source ~/FMTC_intern/install/setup.bash` (`.bashrc`에 들어 있음).
`min_slope`, `right1`, `roi_top`, `steer_filter_n`은 **넣지 않는다**(기본값).

## 5. 튜닝 방법 (순서대로)

**원칙: 한 번에 하나만 바꾼다. 항상 기준선으로 돌아갈 수 있게 한다. 후보는 먼저 저장된 영상으로 거르고 현장에서는 가장 유망한 하나만 시험한다.**
(오늘 `min_slope`, `right1`, `roi_top`, `th_scale`을 연달아 바꿔서 어떤 변화 때문인지 구분이 안 되고 오히려 나빠졌다.)

### 5.0 시험 전 환경 점검 (매번)

1. `ros2 node list | sort | uniq -c` → **모든 노드가 1개씩**. 같은 노드가 둘이면 같은 토픽에 이중 발행되어 결과가 오염된다. (오늘 시험용 노드가 남아 여러 기록이 오염됐다.)
2. `ls /dev/arduino_mega /dev/cam_lane /dev/cam_front /dev/input/js0` 모두 존재. 허브가 한 번 빠졌다 돌아오면 `usb_cam`이 죽어 있으므로 **launch를 껐다 다시 켠다**.
3. `cat /sys/module/usbcore/parameters/autosuspend` = `-1`.
4. launch를 켠 뒤 약 10초 기다렸다가 A (Arduino가 리셋·캘리브레이션 중).
5. 정지 수단: 조이스틱 **Y**, 보조로 터미널 `Ctrl+C`.

### 5.1 기준자세 보정 (조향이 한쪽으로 쏠릴 때 가장 먼저)

1. 차를 트랙에서 **가고 싶은 위치와 방향**에 정확히 놓는다. (오른쪽 경계선이 화면 오른쪽에 보이게. 차선이 안 보이면 측정이 안 된다.)
2. `python3 scripts/lane_tuning/calib_pose.py` (5초 측정, 표준편차가 작아야 한다: 기울기 <0.05, 위치 <30px)
3. 출력의 `제안: -p guide_slope:=... -p guide_x:=...`을 `lane_trace` 실행 명령에 넣는다.
4. 확인: 그 자세에서 `/cmd_lane`의 `z`가 0 근처여야 한다. (`ros2 topic echo /cmd_lane --once`)

카메라 위치/각도를 바꾸면 **반드시 다시** 한다.

### 5.2 측정하는 방법 (rosbag)

```bash
ros2 bag record -o /tmp/bagN /cmd_lane /cmd_auto /cmd_out /light_stop /cross_stop /drive_mode /joy /cam_lane/image_raw
python3 scripts/lane_tuning/bag_summary.py /tmp/bagN           # 2초 단위 표
python3 scripts/lane_tuning/bag_montage.py /tmp/bagN /tmp/m.png 8 22 31 34   # 장면 확인
```

`bag_summary` 읽는 법:
- `lane 전진%`가 낮다 → 차선을 놓치는 중. 영상(`bag_montage`)으로 이유를 본다.
- `out 전진%`가 `lane 전진%`보다 훨씬 낮다 → `cmd_mux`/`decision_auto`가 막는 중(모드, STALE).
- `|z|>=900%`가 높다 → 조향 포화. 어떤 장면인지 `bag_montage`로 확인.
- 조향 평균이 한쪽으로 몇 초 이상 큰 값 → 차가 그쪽으로 계속 보정 중(헤딩/위치 오차가 큼).

### 5.3 후보 설정을 영상으로 먼저 거르기

```bash
python3 scripts/lane_tuning/bag_param_sweep.py --bag /tmp/bag5 --lo 6 --hi 36 \
    --param min_slope 0.4 0.35 0.3 --fixed guide_x=531 guide_slope=0.524
```

세 숫자를 **같이** 본다 (한 숫자만 보면 속는다):
- 검출% 높음 + 포화% 낮음 + 변화량 낮음 = 좋은 후보
- 검출%만 오르고 포화%/변화량이 같이 오르면 엉뚱한 선을 잡는 것이니 버린다.
- 여러 상황(`--bag` 반복: 직선 위주 기록 + 코너 위주 기록 + 중앙 자세 기록)에서 모두 이득인지 본다. 한 기록에서만 좋은 것은 위험하다.

오늘 영상 재생으로 확인한 결과:

| 변경 | 결과 | 채택? |
|---|---|---|
| `min_slope 0.1 + right1 200` | 포화 10%→24%, 변화량 76→165 (주차 박스선) | **버림** |
| `right1` 250/200 만 낮춤 | 포화 10%→17~18% | 버림 |
| `roi_top 280` | 직선 포화 0% 하지만 중앙 자세에서 검출 2%, 코너 28% | **버림** (위치 의존) |
| `steer_filter_n 5` | 튐 5.6%→2.0%, 변화량 151→40 | **후보** (현장 미검증) |
| `min_slope 0.35` | 중앙 자세 기록 검출 34%→73% / 잘 되던 기록은 포화 4.8%→11.3% | **후보** (맞교환, 현장 미검증) |

### 5.4 단계별 튜닝 계획 (권장 순서)

각 단계는 이전 단계가 안정된 뒤에 한다.

**단계 A. 직선 추종 안정화** (현재 거의 도달)
- 기준선 + `calib_pose` 보정. 직선에서 `|조향|`이 0 근처(±100~200)로 수렴하고 전진 100%여야 한다.
- 안 되면: 5.1 재보정 → `guide_x`를 20px씩 조정 → 조향 진동이면 `steer_filter_n:=5` 시험.

**단계 B. 차선 놓침 줄이기**
- 후보: `min_slope:=0.35` (한 번에 하나). `bag_summary`에서 `lane 전진%`가 오르고 `|z|>=900%`가 크게 안 오르면 채택.
- `lost_hold_s`는 1.0~2.0 사이에서. 너무 크면 선을 잃고 질주.

**단계 C. 속도 올리기** (A, B가 안정된 뒤)
- `th_scale`을 **50~100씩** 올리고 같은 구간을 다시 기록. `|z|>=900%`가 늘거나 트랙을 벗어나면 직전 값이 한계.
- 현재 한계 추정: **450 가능, 600은 이탈**. 속도를 올릴 때 조향이 못 따라가는지가 기준이다.
- 속도를 조향 크기에 따라 줄이는 방법(코너에서 감속)은 6.2 참고.

**단계 D. 코너 추종** (가장 큰 개선 여지)
- 6.1(점선 병행) 또는 6.3(곡선/추적 ROI)을 구현. 코너 위주 기록에서 검출률 26%를 70% 이상으로.

**단계 E. 조향 응답/진동**
- 게인 `a_rad`, `b_rad`를 파라미터로 열고(3.4) 낮춰서(예: `b_rad` 0.0027→0.002) 진동이 줄면 채택. 너무 낮추면 보정이 느려 이탈.
- 6.4(펌웨어)를 검토.

### 5.5 증상별 빠른 진단표

| 증상 | 먼저 볼 것 | 흔한 원인 |
|---|---|---|
| 앞으로 안 감, 조향만 됨 | `ros2 topic echo /cmd_auto --once` | 신호 입력 없음(`sign_detect` 꺼짐/`cam_front` 없음) → STALE, 또는 차선 미검출(`x=0`) |
| 한쪽으로 계속 꺾임 | 이상 자세에서 `/cmd_lane`의 `z` | `guide_slope/guide_x` 보정 안 됨 |
| 조향이 ±1000을 오감 | `bag_montage`로 해당 시각 | 엉뚱한 선(주차 박스 등), 조건을 너무 완화함 |
| 전진 명령이 깜빡임 | `lane 전진%` | 검출 깜빡임 → `lost_hold_s` |
| 터미널에 아무것도 안 뜸(lane_trace) | `ros2 topic hz /cam_lane/image_raw` | 카메라 영상이 안 들어옴(허브 끊김, usb_cam 죽음) |
| 새 설정이 안 먹음 | `ros2 node list | sort | uniq -c`, `pgrep -af lane_trace` | 이전 노드가 안 죽고 같이 발행 중 |
| 노드가 갑자기 다 죽음 | `journalctl -k --since -2min | grep -i disconnect` | 허브 끊김 → launch 재시작 |
| `/cmd_out`이 0 | 모드(A를 눌렀나) | STOP 모드, 또는 `/cmd_auto` 0.3초 끊김으로 수동 전환 |

## 6. 앞으로 바꿀 것 (아이디어와 설계)

### 6.1 점선(중앙선)도 같이 보기 — 가장 효과가 클 것으로 기대 **[미구현]**

문제: 오른쪽 경계선 하나만 보면 코너에서 선이 휘어 빠지거나(검출률 26%) 기울기 조건에 걸려 놓친다.
트랙에는 왼쪽에 **흰 점선(중앙선)** 이 있고, 코너에서도 화면 안에 남아 있는 경우가 많다(오늘 영상에서 확인).

설계 초안:
1. 오른쪽 후보(현재 로직)와 **왼쪽 후보**를 따로 구한다. 왼쪽 ROI는 `x < 330` 쪽, 선 기울기 **부호가 오른쪽 선과 반대**(이미지 좌표에서 왼쪽 점선은 위로 갈수록 오른쪽으로 기움).
2. 두 선이 모두 있으면 `y=300`에서의 x 두 개로 **차선 중앙** `x_c = (x_left + x_right)/2`를 구하고, 조향을 `x_c − 이상적_x_c`로 계산. 둘 중 하나만 있으면 지난번 측정한 **차선 폭(px)** 의 절반을 더하거나 빼서 중앙을 추정.
3. 점선은 **끊기는 구간**이 있으므로 0.3~0.5초 홀드 + 중앙값 필터가 필수. 점선 검출이 한동안 없으면 오른쪽 선만 사용.
4. 보정: `calib_pose.py`를 확장해 기준 자세에서 왼/오 x와 기울기, 차선 폭을 함께 측정.
5. 검증은 `bag_param_sweep.py`에 같은 방식으로 후보를 추가해 기록 영상으로 먼저 한다. 코드는 `lane_detect`를 건드리지 않고 별도 함수(`lane_detect_lr`)로 만들고 파라미터 `use_left_line`(기본 false)로 켠다.

위험: 점선이 아닌 구조물(주차 박스선, 반대편 차선)을 잡으면 중앙이 틀어짐 → 기울기 부호와 x 범위 조건을 엄격히.

### 6.2 속도를 조향에 연동 (코너 감속) **[미구현]**

`linear.x = linear_speed × (1 − k × |steering_rad|/0.4)` 처럼 조향이 클수록 감속. 코너에서 이탈하는 문제(속도가 조향 능력을 앞지름)를 줄이는 가장 단순한 방법.
파라미터 `speed_drop_gain`(기본 0)로 열고, 단계 C와 함께 시험.

### 6.3 코너에서 선이 휘어 빠지는 문제의 다른 해법 **[미구현]**

- **이전 프레임 추적 ROI**: 지난 프레임에서 선이 있던 위치 주변으로 ROI를 따라 이동.
- **곡선 피팅**: 직선 대신 2차 곡선(`polyfit deg=2`)으로 피팅하고 곡률을 조향에 추가.
- **Bird's-eye(원근 보정)**: 호모그래피로 위에서 본 평면으로 펴면 선의 기울기가 카메라 각도에 덜 의존해 `guide_slope` 문제가 줄고 곡률 계산이 쉬움. 카메라 고정 후 4점으로 한 번 보정.
- 단, 이런 변경은 후보를 영상 재생으로 비교한 뒤 도입.

### 6.4 조향/구동 액추에이터 쪽 (Arduino 펌웨어, `Arduino/S1/S1.ino`) **[미검증 가설 포함]**

현재 조향은 목표 대비 3~4° 밖이면 PWM 150으로 on/off. 개선 후보:
- **비례 PWM**: `pwm = clamp(Kp × 오차°, 최소, 최대)`. 목표에 가까울수록 약하게 돌려 "달달" 줄임.
- `STEER_PWM_RUN` 150을 낮추기(예: 100), `STEER_DEAD_BAND_DEG`/`STEER_HYST_DEG` 조정.
- `DRIVE_MIN_PWM`을 구동 모터의 실제 최소 구동값으로 설정(현재 0이라 낮은 PWM에서 모터가 안 돎).
- 조향 모터 PWM이 클 때 구동이 멈칫하는지 확인하는 시험: 수동 모드에서 (1) 조향 없이 전진, (2) 조향하며 전진을 비교. 멈칫하면 전원/배선(모터 전원 분리, 커패시터, 굵은 전선) 점검.
- 펌웨어를 올리려면 Arduino IDE 또는 `arduino-cli`가 필요하다. 이 머신에는 아직 설치되어 있지 않다. 올리면 반드시 `calibrateSteering()`이 도는지 확인.
- 보드가 리셋될 때(포트를 열 때)마다 캘리브레이션 동작이 있다. USB 재연결이 잦으면 이것도 멈칫으로 보인다.

### 6.5 제어기 개선 **[미구현]**

- 현재는 사실상 **P 제어**(오차 → 조향). 진동이 있으면 **미분(D) 항** 또는 조향 변화율 제한(레이트 리미터) 추가.
- 한 프레임에서 조향이 변할 수 있는 최대 양을 제한하면 엉뚱한 선 한 프레임에 의한 튐이 줄어든다(중앙값 필터와 병행 가능).
- 카메라 영상 주기가 5~11Hz로 낮다. 허브 대역폭/`sign_detect` CPU 사용이 영향. 영상이 느릴수록 조향이 늦다. 해상도를 줄이거나 `sign_detect`를 낮은 주기로 돌리는 것도 방법.

## 7. USB 구성과 알려진 하드웨어 문제

### 7.1 현재 연결 구조

연결 그림은 한 곳에만 둔다: [인수인계 문서](handoff_2026-10-11.md)의 "USB 연결 상태" 참고. (노트북 USB-C 2개는 휴대폰 테더링·조이스틱, USB-A는 허브 → Arduino·다른 허브(카메라·라이다))

`lsusb -t`에서 허브 안에 허브가 보이는 것은 이 2단 구성 때문이다. 노트북에는 USB-A 1개, USB-C 2개뿐이고 지금 셋 다 사용 중이며,
블루투스/Wi-Fi 드라이버가 없다(6.8 커널). 사용자에게 C→A 변환 어댑터는 없다.

### 7.2 겪은 문제와 대응

| 증상 | 확인 방법 | 대응 |
|---|---|---|
| Arduino가 몇 초마다 끊김 (`disabled by hub (EMI?)`) | `journalctl -k`, `lsusb` 장치 번호 변화 | **USB 자동 절전 끄기**(해결됨, GRUB 영구) |
| 허브 아래 장치가 한꺼번에 사라짐 (`-71`, `unable to enumerate`) | 같은 로그 | 허브 케이블/전원 다시 꽂기. 재부팅이 풀어 준 적 있음 |
| 허브 USB 2.0 쪽만 인식 실패(3.x 쪽만 보임) | `lsusb -t`에서 `Bus 04`에만 허브 | 포트에 따라 달라짐. 케이블/포트 재시도 |
| 허브가 빠졌다 돌아온 뒤 카메라 영상이 없음 | `ros2 node list`에 `usb_cam` 없음 | **launch를 껐다 다시 켠다** |
| C920이 3대로 보임 | `lsusb \| grep C920` | 인식 직후 일시적 중복으로 보이고 곧 정리됨 |

launch를 켤 때마다 허브가 한 번 흔들리는 경향이 있었다(카메라 2대 동시 시작 + Arduino 포트 열림 리셋). **[추정]**

| `bag_summary.py` | rosbag 제어 체인을 2초 단위로 요약 (전진%, 조향, 포화, 버튼/모드) |

| `bag_montage.py` | 원하는 시각의 프레임을 인식 결과(overlay)와 함께 몽타주로 저장 |
| `scripts/s1_status.sh` | 노드/토픽 주기 스냅샷 (참고: 토픽이 안 오면 `ros2 topic hz`가 안 끝나 멈출 수 있음) |

모두 워크스페이스를 `source`한 터미널에서 실행한다. rosbag은 `.db3`(sqlite3) 형식을 읽는다.

## 9. 오늘의 기록 이력 (재현·비교용)

모든 기록은 60초 안팎, `/tmp` 아래라 재부팅하면 사라진다. 결과만 남긴다.

## 10. 바로 이어서 할 일 (우선순위)

1. 기준선으로 한 번 더 주행·기록해서 bag5 결과를 재현하는지 확인 (허브 안정 상태에서).
2. **한 번에 하나**: `-p min_slope:=0.35`만 추가해 시험, `bag_summary`로 비교. (중앙 자세에서 멈추는 문제 개선 기대)
3. 그다음 `-p steer_filter_n:=5`만 추가해 시험.
4. 수동 모드에서 "조향 없이 전진 / 조향하며 전진" 비교로 멈칫 원인(전력 간섭) 확인.
5. `a_rad`, `b_rad`, `speed_drop_gain`을 파라미터로 열고 시험.
6. 점선 병행(6.1) 설계를 구현하고 기록 영상으로 검증.
7. 속도(`th_scale`)는 위 단계가 안정된 뒤 50씩.
8. 이 문서와 `docs/field_notes_2026-10-11.md`의 기준선·교훈을 항상 최신으로 유지.
