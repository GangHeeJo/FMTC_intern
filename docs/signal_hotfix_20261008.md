# 공통 신호 안전 핫픽스 — 2026-10-08 v2

이 수정은 기존 `lane_trace → decision_auto → cmd_mux → serial_sender → Arduino` 구조에서 사용한다. 새 lattice·후진 복구 패키지를 설치해야만 적용되는 기능이 아니다. 수정 전 원본과 이전 v1 묶음은 보존한다.

## 변경된 판단

- 한 프레임에 초록 검출 박스가 여러 개 있어도 한 번만 집계한다.
- 같은 원본 시각의 영상을 재전송하거나 역순으로 보내도 독립된 관측으로 세지 않는다.
- 원본 시각이 오래됐거나 미래인 영상, 변환/추론 실패, 처리 중 유효시간이 지난 결과는 정지 두 개를 발행한다. 잘못된 입력으로 이전의 출발 허용 값을 갱신하지 않는다.
- 빨강·노랑 정지가 확인된 뒤에는 검출이 사라져도 정지를 유지한다. 해제에는 **연속해서 수락된 서로 다른 초록 영상 3장**이 필요하다. 유효한 빈 영상이나 빨강·노랑이 중간에 들어오면 초록 연속 집계가 끊긴다.
- 빨강/노랑과 초록이 동시에 검출되면 즉시 정지를 유지한다. 일반 빨강·노랑 및 횡단보도는 기존 5장 중 3장 집계를 유지한다.
- 0.5초 이상의 입력 공백 뒤에는 과거 투표 창을 비우며 빨간불 정지 상태는 보존한다. 기본 시간값은 현장 지연을 측정해 선정한 값이 아니다.

시각 없는 Boolean 신호 토픽과 기존 우선순위는 유지한다. 기존 판단기는 정지 신호를 장애물 회피보다 먼저 적용한다. 새 후보의 신호 어댑터도 같은 인식 코드를 재사용하고, 실패 결과는 명시적인 `valid=false`로 전달해 이전 초록 허용을 무효화한다.

## 구분해야 하는 한계

‘원본 시각이 서로 다르다’는 내용이 서로 다른 영상이라는 증명이 아니다. 드라이버가 멈춘 화면에 새 시각을 붙이는 고장은 별도 검사 대상이다. 실제 여러 신호등 중 어느 것이 우리 차선의 신호인지 연결하는 기능도 아직 없다. 검출 박스 개수 중복 처리와 신호등·차선 연관성 판단은 별개다.

현재 코드의 횡단보도 검출은 **정지선 거리나 교차로 진입 판정이 아니다**. 정지선을 조금 넘은 것, 차량 앞부분이 교차 통행 구역에 들어간 것, 뒷부분까지 완전히 빠져나온 것은 구분해야 한다. 따라서 이번 핫픽스에는 ‘이미 선을 넘었으니 빨간불 무시’나 ‘일정 시간이 지나면 무조건 출발’ 조건을 넣지 않았다.

이미 진입한 구역에서 안전하게 빠져나가는 정책은 차량 위치·진입 구역·출구 경로·최신 장애물·해당 진행 방향의 신호가 연결된 뒤 별도로 구현할 기능이다. 후진이나 정지 자체를 항상 가장 안전한 행동이라고 보장하지 않는다.

## 검증

`python3 -m unittest discover -s tests -v`로 실제 콜백을 가짜 검출·시계·메시지에 연결한다. 여러 초록 박스, 중복 영상, 상충 신호, 입력 공백·처리 지연, 정지 판단이 최종 `TH:0`까지 전달되는지를 확인한다. 모델 정확도·ROS/DDS·차량 제동·실차 안전성 검증은 아니다.
