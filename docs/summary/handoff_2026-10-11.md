# 10/11 인수인계 (먼저 이것만 읽으세요)

2026-10-11에 조강희가 **네이티브 Ubuntu 22.04**에서 실차(Arduino + C920 2대 + 조이스틱)로 자동 주행을 처음 돌려 본 결과입니다.
브랜치: `ganghee` (main은 건드리지 않았습니다).

## 한 줄 요약

카메라 → 차선 인식 → 제어 → 모터 **체인 전체가 실차에서 동작**하고, **직선은 따라갑니다.** 코너는 아직 못 따라갑니다. 속도는 `th_scale 450`이 한계였습니다.

## 가장 중요한 발견 2가지

1. **Arduino가 몇 초마다 USB에서 끊기던 원인은 USB 자동 절전**이었습니다. 새 머신에서는 GRUB에 `usbcore.autosuspend=-1`을 넣어야 합니다 (`NATIVE=1 bash scripts/vm_setup.sh`가 이 단계까지 해 줍니다).
   (코드/케이블/허브 문제가 아니었는데 오래 헤맸습니다.) 방법은 `docs/records/field_notes_2026-10-11.md`.
2. **차선 기준값(`guide_x`, `guide_slope`)이 카메라 설치에 맞게 다시 측정돼야 합니다.** 기본값(550, 1.11)으로는 이상적인 자세에서도 조향이 한쪽 최대로 쏠립니다.
   [`scripts/lane_tuning/calib_pose.py`](../../scripts/lane_tuning/calib_pose.py)로 5초 측정하면 됩니다.

## 지금 가장 잘 됐던 설정으로 돌리는 법

```bash
# 터미널 1 (th_scale은 s1_stack/config/s1_stack.yaml에서 450으로 임시 변경해서 사용. 이 파일은 커밋하지 않음)
ros2 launch s1_stack s1_stack.launch.py
# 터미널 2
ros2 run lane_trace lane_trace --ros-args -p linear_speed:=1.0 -p lost_hold_s:=1.5 -p guide_slope:=0.524 -p guide_x:=531
# 터미널 3
ros2 run sign_detect sign_detect --ros-args -p model_path:=$HOME/FMTC_intern/sign_detect/best_0808.pt
```

- 조이스틱(Xbox 유선): **A=자동, B=수동, Y=정지**. 시작은 STOP이라 A를 눌러야 합니다. (README에는 정지가 X로 적혀 있으나 실제 설정은 Y)
- `guide_slope:=0.524 -p guide_x:=531`은 **이 카메라 위치에서 잰 값**입니다. 카메라를 옮기면 다시 재야 합니다.
- launch 후 약 10초 기다렸다가 A. 허브가 한 번 빠졌다 돌아오면 launch를 껐다 다시 켜세요(`usb_cam`이 죽어 있음).

## 코드 변경 (이 브랜치, main 대비)

| 파일 | 변경 | 기본 동작 변화 |
|---|---|---|
| `s1_stack/s1_stack/serial_sender.py` | USB가 끊겨도 죽지 않고 정지 상태로 대기, 1초마다 자동 재연결 | 끊김 시 죽던 것이 안 죽음 |
| `lane_trace/lane_trace/lane_trace.py` | 파라미터 추가: `linear_speed`, `lost_hold_s`, `guide_x`, `guide_slope`, `min_slope`, `right1`, `roi_top`, `steer_filter_n` | **없음**(기본값은 기존과 동일) |
| `scripts/lane_tuning/` | 보정/rosbag 분석 도구 4개 | 신규 |
| `s1_stack/s1_stack/decision_auto.py`, `cmd_mux.py`, `sign_detect/*` | 10/10에 minjune 브랜치 안전성 수정을 일부 포팅 (오늘 작업 아님) | |

**병합 주의**: `minjune` 브랜치도 `serial_sender.py`, `decision_auto.py`, `cmd_mux.py`, `lane_trace.py`, `s1_stack.yaml`을 수정했습니다. 병합하면 충돌할 가능성이 큽니다.
특히 minjune의 `serial_sender` 재작성 버전에도 재연결 로직(이 브랜치의 `try_open`/`drop_serial`)을 옮겨야 합니다.

## 아직 안 되는 것 (우선순위)

1. **코너 추종**: 오른쪽 경계선만 보는 구조라 코너에서 선이 화면 밖으로 휘어 빠져 놓칩니다(코너 구간 검출 약 26%). 왼쪽 점선(중앙선)도 같이 보게 만드는 것이 가장 효과가 클 것으로 봅니다(설계는 가이드 6.1).
2. 조향/전진이 번갈아 멈칫하는 현상: 명령은 끊기지 않았는데 차가 멈칫. 조향 모터와 구동 모터의 전력 간섭 의심(미검증).
3. 속도: `th_scale 600`은 조향이 못 따라가 이탈. 450까지만 확인.
4. 조향 게인(`a_rad`, `b_rad`)이 아직 파라미터로 안 열려 있음.

## 아직 검증 못 한 것

`sign_detect` 실제 인식, 라이다 노드(`obs_evade` 등), 허브 연결의 장시간 안정성, `min_slope:=0.35`·`steer_filter_n:=5`의 실주행 효과(기록 영상 재생에서는 개선).

## 하드웨어 환경 주의

- 노트북에 USB-A 1개, USB-C 2개뿐이고 블루투스/Wi-Fi가 안 됩니다(커널 6.8이 칩을 지원 안 함). 인터넷은 iPhone 테더링.
- USB 연결 상태 (노트북 포트 3개를 모두 사용 중):

```
노트북
├─ USB-C ① ── 휴대폰(iPhone) : 인터넷용 USB 테더링
├─ USB-C ② ── Xbox 컨트롤러(조이스틱) : C to C 케이블
└─ USB-A   ── "A to A 허브" ──┬── Arduino
                              └── 다른 허브 ──┬── 카메라 2대 (C920)
                                              └── 라이다 (현재 뺌)
```

  허브가 2단이라 부하에서 가끔 장치가 한꺼번에 빠집니다. 빠지면 `usb_cam`이 죽으므로 launch를 다시 켜세요.
