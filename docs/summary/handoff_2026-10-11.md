# 10/11 인수인계 (먼저 이것만 읽으세요)

2026-10-11에 조강희가 **네이티브 Ubuntu 22.04**에서 실차(Arduino + C920 2대 + 조이스틱)로 자동 주행을 처음 돌려 본 결과입니다. 브랜치는 `ganghee`입니다 (main은 건드리지 않았습니다).

순서: **1. 연결 → 2. 초기 설정(처음 한 번) → 3. 실행(매번)** 이고, 그 뒤에 현재 상태와 주의사항이 있습니다.

---

## 1. 연결 방법

```
노트북
├─ USB-C ① ── 휴대폰(iPhone) : 인터넷용 USB 테더링 (Wi-Fi가 안 되기 때문)
├─ USB-C ② ── Xbox 컨트롤러(조이스틱) : C to C 케이블
└─ USB-A   ── "A to A 허브" ──┬── Arduino (새 USB 케이블)
                              └── 다른 허브 ──┬── 카메라 2대 (Logitech C920)
                                              └── 라이다 (지금은 뺌)
```

순서:
1. 허브 전원선을 멀티탭에 꽂는다 (허브는 외부 전원이 필요함).
2. 노트북 USB-A에 허브를 꽂고, 허브에 Arduino와 다른 허브를 꽂고, 다른 허브에 카메라 2대를 꽂는다.
3. 노트북 USB-C ②에 조이스틱을 꽂는다.
4. **연결 확인 명령** (모두 나와야 정상):

```bash
ls /dev/arduino_mega /dev/cam_lane /dev/cam_front /dev/input/js0
```

| 이름 | 무엇 | 안 나오면 |
|---|---|---|
| `/dev/arduino_mega` | 모터·조향을 제어하는 Arduino Mega | 케이블/허브 확인 |
| `/dev/cam_lane` | **차선용** 카메라 | 해당 C920 확인 (시리얼로 구분됨) |
| `/dev/cam_front` | **전방(신호등용)** 카메라 | 〃 |
| `/dev/input/js0` | 조이스틱 | USB-C ② 확인 |
| `/dev/rplidar` | 라이다 (쓸 때만) | |

- 이 이름들은 장치의 **시리얼 번호**로 정해집니다 (`udev/99-robot.rules`). **다른 장치로 바꾸면 이름이 안 생깁니다.** 그때는 `udevadm info -a -n /dev/videoN | grep serial`로 시리얼을 확인해 규칙 파일의 값을 바꾸세요.
- 실제 장치 번호(`ttyACM0`↔`ttyACM1`, `ttyUSB0`↔`ttyUSB1`, `video0`↔`video4` 등)는 꽂을 때마다 바뀝니다. 항상 **위의 `/dev/…` 이름**(udev 링크)만 쓰세요.
- 허브가 2단이라 부하에서 장치가 한꺼번에 빠질 때가 있습니다. 빠지면 `usb_cam` 노드가 죽으므로 **launch를 다시 켜세요.**
- Wi-Fi/블루투스는 안 됩니다 (커널 6.8이 이 노트북 칩을 지원하지 않음). 조이스틱은 반드시 유선.

## 2. 초기 설정 (새 머신에서 처음 한 번)

일반 터미널에서 실행하세요 (`sudo` 비밀번호를 입력해야 해서 Claude Code의 `!` 명령으로는 안 됩니다).

| 순서 | 명령 | 하는 일 |
|---|---|---|
| ① | `git clone https://github.com/GangHeeJo/FMTC_intern.git ~/FMTC_intern`<br>`cd ~/FMTC_intern && git checkout ganghee` | 코드를 받고 `ganghee` 브랜치로 이동 |
| ② | `NATIVE=1 bash scripts/vm_setup.sh 2>&1 \| tee ~/vm_setup.log` | **한 번에 전부 설치** (아래 설명). 시간이 오래 걸림(torch 다운로드). 중간에 `sudo` 비밀번호 입력 |
| ③ | `sudo reboot` | 그룹 권한(`dialout`, `video`)과 USB 절전 설정을 적용 |
| ④ | 아래 확인 명령 3개 | 설치가 제대로 됐는지 확인 |
| ⑤ | `s1_stack/config/s1_stack.yaml` 수정 (아래) | **속도 제한**과 조이스틱 축 설정. **커밋 금지** |
| ⑥ | `python3 scripts/lane_tuning/calib_pose.py` | 카메라 위치에 맞는 차선 기준값 측정 (카메라를 옮길 때마다) |

**② `NATIVE=1 bash scripts/vm_setup.sh`가 하는 일**

ROS2 humble 설치(저장소 등록 + `ros-humble-desktop`), 카메라/조이스틱 패키지(`usb-cam`, `cv-bridge`, `joy`), 빌드 도구(`colcon`), `ultralytics`/`torch`(신호등 인식), `pyserial`(Arduino 통신), `setuptools==58.2.0`·`numpy<2.0` 고정, 시리얼/카메라 접근 권한 부여(`dialout`, `video`), `colcon build`, `udev` 규칙 복사(장치 이름 `/dev/arduino_mega` 등), `~/.bashrc`에 ROS 환경 등록, **USB 자동 절전 끄기**(`NATIVE=1`일 때만).
`NATIVE=1`을 빼면 VM/WSL용(CycloneDDS 사용, USB 절전은 건드리지 않음)으로 동작합니다.

**④ 확인 명령 (재부팅 후)**

```bash
cat /sys/module/usbcore/parameters/autosuspend   # -1 이어야 함 (USB 자동 절전이 꺼져 있음. 안 꺼져 있으면 Arduino가 몇 초마다 끊김)
groups | grep -E "dialout|video"                 # 둘 다 나와야 함 (시리얼/카메라 권한)
ros2 pkg list | grep -E "lane_trace|sign_detect|s1_stack"   # 세 패키지가 나와야 함 (빌드 성공)
```

**⑤ `s1_stack/config/s1_stack.yaml` 수정 (로컬에서만, 커밋 금지)**

```bash
cd ~/FMTC_intern
sed -i 's/^    th_scale: .*/    th_scale: 450   # 임시 저속 (기본 1000), 커밋 금지/' s1_stack/config/s1_stack.yaml
sed -i 's/^    axis_steer: .*/    axis_steer: 3   # Xbox 오른쪽 스틱 좌우/; s/^    axis_drive: .*/    axis_drive: 1   # Xbox 왼쪽 스틱 상하/' s1_stack/config/s1_stack.yaml
```

| 설정 | 의미 |
|---|---|
| `th_scale` | 최대 속도 제한. 기본 1000이면 빠름. **처음에는 200~450으로** (450이 오늘 확인한 한계, 600은 조향이 못 따라가 이탈) |
| `axis_steer`, `axis_drive` | 조이스틱 축 번호. Xbox 컨트롤러 기준으로 오른쪽 스틱 좌우=조향, 왼쪽 스틱 상하=전후진 (기본값은 다른 컨트롤러 기준이라 안 맞음) |

## 3. 실행 (매번)

터미널 3개를 열어 **차례로** 실행합니다 (각각 `source`는 `.bashrc`에 있어서 자동).

| 터미널 | 명령 | 하는 일 |
|---|---|---|
| **1** | `ros2 launch s1_stack s1_stack.launch.py` | **메인 스택 전체**: 조이스틱 입력, 모드 선택(`cmd_mux`), 최종 제어 결정(`decision_auto`), Arduino로 시리얼 전송(`serial_sender`), 카메라 2대, 라이다를 한꺼번에 띄움. 라이다를 안 꽂았으면 라이다 에러가 나지만 무시해도 됨 |
| **2** | `ros2 run lane_trace lane_trace --ros-args -p linear_speed:=1.0 -p lost_hold_s:=1.5 -p guide_slope:=0.524 -p guide_x:=531` | **차선 인식**: 차선 카메라 영상에서 오른쪽 차선을 찾아 조향/전진 명령을 만듦 |
| **3** | `ros2 run sign_detect sign_detect --ros-args -p model_path:=$HOME/FMTC_intern/sign_detect/best_0808.pt` | **신호등/횡단보도 인식**(YOLO): 전방 카메라에서 찾아 정지 신호를 만듦. **이게 꺼져 있으면 자동 주행이 안 감** (정지 신호 입력이 없으면 안전을 위해 정지) |

터미널 2의 옵션 설명:

| 옵션 | 의미 |
|---|---|
| `linear_speed:=1.0` | 차선 추종 중 전진 세기(0~1). 실제 속도 = 이 값 × `th_scale` |
| `lost_hold_s:=1.5` | 차선을 놓쳐도 1.5초는 전진과 마지막 조향을 유지 (코너에서 잠깐 놓쳐도 계속 감) |
| `guide_slope:=0.524`, `guide_x:=531` | **이 카메라 위치에서 잰 기준값** (이상적인 자세에서 선의 기울기/위치). 카메라를 옮기면 `calib_pose.py`로 다시 측정 |

**조이스틱 (Xbox 유선)**

| 버튼 | 동작 |
|---|---|
| **A** | **자동 주행 시작** (시작은 STOP이라 A를 눌러야 함) |
| **B** | 수동 모드 (왼쪽 스틱 전후진, 오른쪽 스틱 조향) |
| **Y** | **정지** (비상 정지. README의 X는 틀린 표기) |

**순서**: 터미널 1 → 약 10초 대기(Arduino가 켜지며 조향을 보정함) → 터미널 2, 3 → **A**. 끌 때는 각 터미널에서 `Ctrl+C`. 카메라가 `Device busy`면 `pkill -x usb_cam_node_ex`.

**상태 확인**: `bash scripts/s1_status.sh` (노드/토픽 주기 스냅샷). **처음에는 바퀴를 띄우고** 시험하고, 정지 수단(조이스틱 Y, 터미널 `Ctrl+C`)을 항상 손 가까이에 두세요.

## 4. 현재 상태

카메라 → 차선 인식 → 제어 → 모터 **체인 전체가 실차에서 동작**하고, **직선 차선 추종까지** 확인했습니다. 코너는 아직 못 따라갑니다.

| 기능 | 상태 |
|---|---|
| 차선 추종 (직선) | 동작 |
| 차선 추종 (코너) | 미흡 |
| 신호등/횡단보도 정지 | **미검증** (`sign_detect`는 돌았지만 오늘 기록에서 한 번도 `True`가 안 떴고, 실물을 놓고 시험하지 않음) |
| 장애물 회피 | **미검증** (라이다를 뺀 상태였고 `obs_evade`는 launch에 없음) |
| 주차 | **미구현** |

## 5. 가장 중요한 발견 2가지

1. **Arduino가 몇 초마다 USB에서 끊기던 원인은 USB 자동 절전**이었습니다 (코드/케이블/허브가 아니었는데 오래 헤맸습니다). 위 ②의 `NATIVE=1`이 해결해 줍니다. 수동으로 하는 방법은 [현장 노트](../records/field_notes_2026-10-11.md).
2. **차선 기준값(`guide_x`, `guide_slope`)은 카메라 설치에 맞게 다시 재야 합니다.** 기본값(550, 1.11)으로는 이상적인 자세에서도 조향이 한쪽 최대로 쏠립니다.

## 6. 아직 안 되는 것 (우선순위 3개만, 전체 목록은 [현장 노트 1.4](../records/field_notes_2026-10-11.md))

1. **코너 추종**: 오른쪽 경계선만 보는 구조라 코너에서 선이 화면 밖으로 휘어 빠져 놓칩니다(코너 구간 검출 약 26%). 왼쪽 점선(중앙선)도 같이 보게 만드는 것이 가장 효과가 클 것으로 봅니다(설계는 [가이드 6.1](../records/lane_following_guide.md)).
2. 조향/전진이 번갈아 멈칫하는 현상: 명령은 끊기지 않았는데 차가 멈칫. 조향 모터와 구동 모터의 전력 간섭 의심(미검증).
3. 조향 게인(`a_rad`, `b_rad`)이 아직 파라미터로 안 열려 있음.
