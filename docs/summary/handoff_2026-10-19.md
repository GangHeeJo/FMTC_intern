# 10/19 인수인계 — 차선 카메라 정면 재장착 + 방식 3 조향 + 횡단보도 정지선 (먼저 이것만 읽으세요)

> 상세 기록(시험별 원인·조치): [docs/records/field_notes_2026-10-19.md](../records/field_notes_2026-10-19.md). 이 문서는 10/20에 `gyungyoon/1019` 브랜치를 `main`에 병합하며, 당시 남겨진 적 없던 10/19 기록을 커밋 메시지 49개로 재구성한 것입니다 — 시각 등은 참고용.

작성: 도경윤(실차) / 정리: 10/20 `main` 병합 시. 차선 카메라를 2차선 오른쪽만 보던 각도에서 **정면**으로 재장착.

## 무엇이 되나

- **정면 카메라로 양쪽 차선 추종**: `lane_trace` 방식 3(`detector: 3`)이 왼쪽·오른쪽 선을 각각 찾아 차로 중앙 + 소실점으로 조향. 커브에서 점선 토막을 이어 2차식으로 맞추는 보정까지 포함.
- **횡단보도 정지선 검출**: 신호등 박스 크기 대신, 차선 카메라가 바닥 정지선 자체(`/stop_line_y`)를 보고 "도달했는지"를 판단. `decision_auto`의 `stop_line_mode: true`로 사용.
- **장애물 회피 차선 변경이 vision 모드로**: 시간표 대신 카메라가 보는 새 차선 위치로 각 단계 종료를 판단 — 속도가 바뀌어도 재조정 불필요(10/17 숙제 해결).
- 초록불 인식(`/light_green`) 추가, 신호등 확신도(`light_conf`)·박스 최소 크기(`min_bbox_size`) 파라미터화.
- `serial_sender`의 속도 스케일(`th_scale`)을 노드 재시작 없이 `ros2 param set`으로 바로 변경 가능.

## 실행

```bash
# 1
ros2 launch s1_stack s1_stack.launch.py
# 2
OMP_NUM_THREADS=6 taskset -c 6-11 ros2 run sign_detect sign_detect --ros-args -p model_path:=$HOME/FMTC_intern/sign_detect/best_0808.pt
# 3
taskset -c 0-5 ros2 run lane_trace lane_trace --ros-args --params-file ~/FMTC_intern/s1_stack/config/front_1019.yaml
# 4 (차를 출발 위치에 놓은 뒤, 시험마다 새로)
taskset -c 0-5 ros2 run obs_evade obs_evade --ros-args --params-file ~/FMTC_intern/s1_stack/config/front_1019.yaml
```

- 조이스틱: **A 자동, B 수동, Y 정지**.
- `front_1019.yaml`은 `decision_auto`에도 파라미터를 주므로(`stop_line_mode: true` 등), `decision_auto`도 같은 `--params-file`로 띄워야 함.

## 주의

- **`front_1019.yaml`의 속도·거리 값은 아직 추정치**(PWM이 속도에 비례한다고 가정하고 10/17 실측값을 환산). 실제 속도를 재면 다시 맞출 것.
- `stop_line_mode`의 기본값은 `false` — 파라미터 파일 없이 기본값으로 띄우면 옛날 신호등 판단 방식(+ 장애물보다 신호가 우선인 지금 고쳐진 순서)으로 동작함. 반드시 `front_1019.yaml`(또는 그걸 반영한 설정)을 줄 것.
- `obstacle_1017.yaml`(카메라 오른쪽 시절 설정)과 `front_1019.yaml`(카메라 정면, 지금 기준)은 서로 다른 카메라 각도를 전제로 하므로 **섞어 쓰면 안 됨**.
- `lane_trace`의 `crosswalk_detect` 튜닝 상수(ROI, 줄무늬 조건 등)는 아직 코드에 하드코딩돼 있어 파라미터로 못 바꿈 — 현장에서 조정하려면 코드 수정 + 재빌드 필요.
